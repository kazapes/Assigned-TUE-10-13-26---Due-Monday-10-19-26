## Overview

### Lecture covers AWS billing controls, EC2 introduction, launching instances, instance types, storage, security groups, and SSH access methods. - Focus on practical steps: enable billing access, set budgets, create EC2 instance, configure user data, manage security groups, and connect via SSH or EC2 Instance Connect.
 ## Billing And Budgets - 
 
 #### IAM users may be denied billing; enable "IAM user and role access to billing information" from the root account. - Billing console shows cost breakdown, monthly forecast, and charges by service. - Bills -> select month -> scroll to "charges by service" to see detailed per-service costs. - Free Tier dashboard shows current and forecasted usage against free limits; forecast in red indicates potential billing. - Budgets: - Create budgets in Billing console -> Budgets. - Templates: zero-spend (alert at $0.01) and monthly cost budgets (e.g., $10/month). - Configure alert thresholds (e.g., 85% actual, 100% actual, 100% forecast) and notification emails. 

 ## EC2 Introduction - EC2 = Elastic Compute Cloud; Infrastructure as a Service (IaaS) for renting virtual servers. - EC2 components: Instances (VMs), EBS volumes, Elastic Load Balancers, Auto Scaling Groups. - Instance configurable options: - Operating system: Linux, Windows, macOS. - CPU, RAM, storage type (EBS, EFS, instance store). - Network options: NIC performance, public IP, security groups (firewall). - Bootstrapping via EC2 user data (runs once as root on first launch). 
 
 ## EC2 User Data (Bootstrapping) - User data: script executed only at first boot to automate setup tasks. - Typical tasks: install updates, install software, download files, configure services. - Scripts run as root (sudo privileges). - Keep scripts simple to reduce boot time complexity. 
 
 ## Launching First EC2 Instance (Step Summary) - EC2 Console -> Instances -> Launch Instances. - Add Name tag (e.g., "my first instance"). - Choose AMI: Amazon Linux 2 (free tier eligible). - Choose architecture: 64-bit x86. - Choose Instance Type: t2.micro (free tier eligible). - Key pair: - Create new key pair (e.g., "EC2_tutorial"). - Key pair type RSA; format: .pem for Mac/Linux/Windows 10+, .ppk for PuTTY on older Windows. - Network & Security: - Assign public IPv4 by default. - Create security group (console creates one, e.g., launch_security_1). - Add inbound rules: SSH (port 22) from your IP or anywhere; HTTP (port 80) for web server. - Storage: - Default root: 8 GB gp2 (general purpose SSD); free tier up to 30 GB. - Note: "Delete on termination" default = yes (root volume deleted when instance terminated). - Advanced -> User Data: - Paste user data script to install web server and start service on first boot. - Launch and verify: - Access instance via public IPv4 + HTTP for web content. - Public IPv4 may change after stop/start; private IPv4 remains constant.
 
 ## EC2 Instance Types (High Level) - Categories: General Purpose, Compute Optimized, Memory Optimized, Storage Optimized, Accelerated Computing, HPC. - Naming convention: class + generation + size (e.g., m5.2xlarge). - Examples: - General purpose (balanced compute/memory/network) — good for web servers. - Compute optimized (C family) — CPU-heavy workloads. - Memory optimized (R, X1, High Memory) — in-memory databases, BI, real-time processing. - Storage optimized (I, D, H1) — high I/O local storage use (OLTP, warehousing). - Example comparisons: - t2.micro: 1 vCPU, 1 GB memory (small, free tier). - r5.16xlarge: 16 vCPU, 512 GB memory (memory-focused). - c5.16xlarge: 16 vCPU, 32 GB memory (compute-focused). - Recommendation: use ec2instances.info for side-by-side instance comparisons and pricing. 
 
 ## Security Groups (Firewall Basics) - Security groups control inbound and outbound traffic to EC2 instances. - Rules only allow; no explicit deny rules. - Rules can reference IP CIDR ranges (IPv4/IPv6) or other security groups. - Typical rule components: Type, Protocol, Port (or port range), Source (CIDR or security group). - Default behavior: - Inbound: all blocked by default. - Outbound: all allowed by default. - Important behaviors: - Security groups are region/VPC scoped. - An instance can have multiple security groups attached. - A security group can be attached to many instances. - Security groups act outside the instance (traffic blocked before reaching instance). - Best practice: separate security group for SSH access to restrict and manage SSH rules easily. - Troubleshooting: - Timeout (connection hangs) => likely security group blocking inbound traffic. - Connection refused => traffic reached instance but application refused or not listening. - Referencing security groups: - You can allow inbound traffic from another security group instead of IPs. - Useful for load balancer and multi-tier architectures to avoid IP management. 
 
 ## Ports To Know (Exam and Practical) - 22 — SSH (Linux) and SFTP (secure file transfer over SSH) - 21 — FTP (insecure file transfer) - 80 — HTTP (insecure web traffic) - 443 — HTTPS (secure web traffic) - 3389 — RDP (Windows Remote Desktop) 
 
 ## Managing Security Group Rules (Practical Steps) - Navigate: EC2 Console -> Networking & Security -> Security Groups. - View inbound/outbound rules, edit to add/remove access. - To restore web access: add inbound HTTP (port 80) from required CIDR (e.g., 0.0.0.0/0 for public). - Use "My IP" to restrict access to your current IP (beware IP changes). - Multiple security groups’ rules accumulate (union of allowed traffic). 
 
 ## SSH And Instance Connect Methods - Options by client OS: - Mac/Linux: native ssh command-line client. - Windows 10 and newer: native ssh or Windows Terminal. - Windows older than 10: PuTTY (requires .ppk key). - EC2 Instance Connect: browser-based web terminal (works across OSes). - EC2 Instance Connect limitation: works with Amazon Linux 2 (used in the course). - Recommendation: - Try EC2 Instance Connect for quick access without installing tools. - Learn SSH basics; SSH is a common source of student issues (check security group rules and keypair). - Troubleshooting tips: - Re-check security group inbound SSH (port 22). - Confirm correct key pair and permissions. - Use EC2 Instance Connect if client-side SSH issues persist.
